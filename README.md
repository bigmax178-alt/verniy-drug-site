# Сайт приюта «Верный друг»

Статический сайт, который сам обновляется из группы ВКонтакте [vk.com/priut_bestfriends_spb](https://vk.com/priut_bestfriends_spb):
приют публикует посты, товары и сообщения в обсуждениях — как всегда, а сайт раз в 30 минут (или мгновенно по Callback API)
забирает всё это, раскладывает по разделам и публикуется заново. Никакой админки.

- **Стек:** [Astro](https://astro.build) (статика), обычный CSS и небольшие скрипты без фреймворков, Node 20.
- **Данные:** `scripts/sync-vk.mjs` → `src/data/vk/*.json` (коммитятся ботом). Пока VK не подключён — `data/seed/*` (снято со старого сайта на Tilda).
- **Хостинг:** GitHub Pages через Actions (`.github/workflows/sync-and-deploy.yml`); подойдёт любой статический хостинг — папка `dist/`.
- **Пожертвования:** QR-код банка, СБП, реквизиты АНО с кнопками «скопировать»; при наличии `CLOUDPAYMENTS_PUBLIC_ID` — оплата картой и ежемесячные списания прямо на сайте (виджет CloudPayments, без сервера).

## Быстрый старт локально

```bash
npm install
npm run seed        # один раз: стартовые данные со старого сайта (уже лежат в data/seed)
npm run dev         # http://localhost:4321
```

С данными из ВКонтакте:

```bash
cp .env.example .env    # впишите VK_TOKEN
VK_TOKEN=... npm run sync && npm run build && npm run preview
```

## Как сайт читает ВКонтакте

| Раздел сайта | Откуда в группе | Метод API |
|---|---|---|
| Новости, сборы, отчёты, «нашли дом» | стена группы (посты раскладываются по хэштегам и ключевым словам) | `wall.get` |
| Ищут дом (каталог, карточки, фильтры) | **Товары** — подборки «Коты и кошки», «Собаки» | `market.get`, `market.getAlbums` |
| Помочь → реквизиты, нужды, пункты сбора, опекунство | обсуждения (id заданы в `site.config.mjs → vk.topics`) | `board.getTopics`, `board.getComments` |
| Отчёты | обсуждения «Финансовый отчёт…», «Отчёт расходов…» + посты-отчёты | то же |
| Нашли дом | посты `#дома` + обсуждение «Приветы от выпускников» | то же |
| О приюте, контакты, цифры | описание и контакты группы | `groups.getById` |
| Фотоальбомы | альбомы группы | `photos.getAlbums` |

Хэштеги, по которым посты попадают в разделы, и id обсуждений — в `site.config.mjs`. Там же реквизиты, телефоны,
суммы-подсказки и всё, что приют может захотеть поменять руками. Памятка для приюта: [`docs/pamyatka.md`](docs/pamyatka.md).

## Подключение ВКонтакте (получить VK_TOKEN)

Нужен любой из двух токенов:

**Вариант А — сервисный ключ доступа (проще, без привязки к человеку).**
1. Зайдите на [vk.com/apps?act=manage](https://vk.com/apps?act=manage) → «Создать приложение» → тип *Standalone*, любое название.
2. Настройки приложения → «Сервисный ключ доступа» — скопируйте.
3. Проверка: `VK_TOKEN=<ключ> npm run sync`. Если в выводе есть предупреждение про `board.getTopics` — обсуждения сервисному ключу недоступны, используйте вариант Б.

**Вариант Б — токен администратора группы (нужно быть админом или попросить админа).**
1. Создайте приложение как в варианте А, запомните его `ID приложения`.
2. Откройте в браузере, подставив ID:
   `https://oauth.vk.com/authorize?client_id=ID&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=groups,wall,market,photos,offline&response_type=token&v=5.199`
3. Разрешите доступ; из адресной строки скопируйте значение `access_token=…` (страница будет пустой — это нормально). Токен бессрочный (`offline`).

Токен даёт **только чтение** открытых данных группы; сайт ничего не публикует в VK.

## Публикация на GitHub Pages

1. Создайте репозиторий, запушьте код в ветку `main`.
2. Settings → Pages → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions:
   - Secrets: `VK_TOKEN`; при наличии `CLOUDPAYMENTS_PUBLIC_ID`, `YANDEX_METRIKA_ID`.
   - Variables: `SITE_URL` (например `https://verniy-drug.ru` или `https://<user>.github.io/<repo>`), `BASE_PATH` (`/` для домена, `/<repo>` для страницы проекта).
4. Actions → sync-and-deploy → Run workflow. Дальше — само, каждые 30 минут.
5. Свой домен: Settings → Pages → Custom domain (+ CNAME у регистратора на `<user>.github.io`), включить HTTPS. `SITE_URL` поменять на домен, `BASE_PATH` на `/`.

Мгновенное обновление по событиям VK — [`callback/README.md`](callback/README.md).

Хостинг в России (Timeweb, reg.ru и т. п.): собирайте в Actions и заливайте `dist/` по FTP/rsync любым готовым action, либо
запускайте `npm run sync:build` кроном на сервере.

## Онлайн-оплата картой

Виджет CloudPayments работает без сервера: достаточно `CLOUDPAYMENTS_PUBLIC_ID` из личного кабинета. Для этого АНО заключает договор
с CloudPayments (у них есть льготные условия для благотворительных организаций); в кабинете нужно указать адрес сайта и загрузить оферту
(`/docs/offer/`). Регулярные пожертвования — через параметр `recurrent` в виджете, отмена — из письма CloudPayments или через кабинет.

Если удобнее другой сервис (ЮKassa, CloudTips, VK Pay) — задайте `EXTERNAL_PAY_URL`: кнопка «Пожертвовать» будет открывать эту ссылку.
Пока ничего не подключено, кнопка ведёт к QR-коду и реквизитам — это уже рабочий способ пожертвовать.

## Структура

```
site.config.mjs          — всё, что правится руками: реквизиты, телефоны, id обсуждений, хэштеги, суммы
scripts/sync-vk.mjs      — синхронизация из VK → src/data/vk/*.json
scripts/import-tilda-seed.mjs — одноразовый импорт со старого сайта → data/seed/
src/lib/data.ts          — единая точка чтения данных (VK → seed)
src/pages/               — страницы: /, /help, /animals, /animals/[slug], /adopted, /news, /news/[id], /reports, /about, /docs/*, /thanks, 404, rss.xml, sitemap.xml
src/components/          — Header, TabBar, DonateWidget, AnimalCard, PostCard, …
callback/                — воркер для мгновенной пересборки по Callback API
docs/                    — памятка приюту, заметки об устройстве группы
```

## Проверка перед релизом

- `npm run build` проходит без ошибок; `npm run preview` — открыть `/`, `/help/`, `/animals/`, любую карточку, `/news/`.
- На `/help/` кнопки «Скопировать» копируют, QR открывается, «Пожертвовать» либо открывает виджет, либо ведёт к QR.
- В футере видна дата последней синхронизации из VK.
