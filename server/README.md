# Админка приюта: развёртывание и закон

## Две сборки одной админки

Код общий (`server/lib/router.mjs`), различается только среда:

| | На Vercel (`api/admin.mjs`) | На сервере в РФ (`server/index.mjs`) |
|---|---|---|
| Карточки животных, фото | ✅ | ✅ |
| Хранилище | git-репозиторий | файлы в `DATA_DIR` |
| Имя и фото опекуна | ❌ только пометка «опекун есть» | ✅ |
| Заявки на опекунство | ❌ отвечает 503 | ✅ |
| Учётная запись | переменные окружения | создаётся при первом входе |

Почему так поделено: имя опекуна и данные из заявки — персональные данные, и
ч. 5 ст. 18 152-ФЗ требует записывать их в базу на территории России. Карточка
животного персональными данными не является, поэтому её можно вести откуда угодно.
Пометка «у животного есть опекун» — тоже: это факт о животном, а не о человеке.

### Запуск на Vercel

1. `node scripts/make-admin-hash.mjs "ваш пароль"` — выдаст хэш и секрет сессий.
2. GitHub → Settings → Developer settings → **Fine-grained tokens**: новый токен на
   один этот репозиторий, право **Contents: Read and write**.
3. Vercel → Settings → Environment Variables:
   `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, `GITHUB_REPO` (владелец/репозиторий), `GITHUB_TOKEN`.
4. Передеплоить. Админка — на `/admin/`.

Сохранение карточки делает коммит в репозиторий, коммит запускает пересборку — сайт
обновляется сам, отдельно ничего запускать не нужно.


Небольшой сервер на Node.js без единой внешней зависимости. Делает три вещи:

1. даёт приюту вести карточки животных (в том числе блок «опекун»);
2. принимает с сайта заявки на опекунство вместе с согласиями на обработку персональных данных;
3. отдаёт публичную часть данных сборщику сайта.

**Заявки и контакты людей никогда не покидают этот сервер:** они не попадают ни в git, ни в сборку сайта, ни на Vercel.

## Почему сервер обязан стоять в России

Часть 5 статьи 18 152-ФЗ запрещает записывать, систематизировать, накапливать, хранить, уточнять и извлекать персональные данные граждан РФ в базах за пределами России. Заявка с именем и телефоном — ровно такая запись.

Практические следствия:

- Обработчик формы **нельзя** делать serverless-функцией Vercel или GitHub — российских регионов у них нет. Штраф за нарушение локализации — от 1 до 6 млн ₽ (ч. 8 ст. 13.11 КоАП, редакция с 30.05.2025).
- Статический сайт на Vercel при этом законен: там нет персональных данных, а форма отправляет их напрямую на российский сервер, минуя Vercel.

## Быстрый старт локально

```bash
npm run admin:dev
```

Откройте `http://localhost:8787/admin/` — сервер предложит создать первую учётную запись.

## Переменные окружения

| Переменная | Зачем | Пример |
|---|---|---|
| `DATA_DIR` | Где лежат данные. Эту папку и надо бэкапить | `/var/lib/verniy-drug` |
| `PORT` | Порт | `8787` |
| `ALLOWED_ORIGINS` | Домены сайта, с которых принимается форма (через запятую) | `https://verniy-drug.ru` |
| `COOKIE_SECURE` | `0` только для локальной отладки по http | — |
| `TRUST_PROXY` | `1`, если сервер стоит за nginx | `1` |
| `PUBLISH_URL` | Куда стучаться по кнопке «Опубликовать» | `https://api.github.com/repos/<owner>/<repo>/dispatches` |
| `PUBLISH_TOKEN` | Токен GitHub с правом Contents: write | — |

## Развёртывание на сервере (пример для Beget/Timeweb/Selectel)

```bash
# 1. Node 20+ и код
git clone <репозиторий> /opt/verniy-drug && cd /opt/verniy-drug
npm ci --omit=dev

# 2. Папка данных, доступная только сервису
sudo mkdir -p /var/lib/verniy-drug && sudo chown $USER /var/lib/verniy-drug && chmod 750 /var/lib/verniy-drug
```

Юнит systemd `/etc/systemd/system/verniy-drug-admin.service`:

```ini
[Unit]
Description=Админка приюта «Верный друг»
After=network.target

[Service]
Type=simple
User=verniydrug
WorkingDirectory=/opt/verniy-drug
Environment=DATA_DIR=/var/lib/verniy-drug
Environment=PORT=8787
Environment=TRUST_PROXY=1
Environment=ALLOWED_ORIGINS=https://verniy-drug.ru
ExecStart=/usr/bin/node server/index.mjs
Restart=always
# Ограничиваем доступ процесса к файловой системе
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
NoNewPrivileges=true
ReadWritePaths=/var/lib/verniy-drug

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now verniy-drug-admin
```

nginx перед ним — обязательно с HTTPS (Let's Encrypt):

```nginx
server {
  server_name admin.verniy-drug.ru;
  client_max_body_size 15m;   # фотографии с телефона
  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

Бэкап (ежедневно, хранить 30 дней):

```bash
tar czf /backup/vd-$(date +%F).tar.gz -C /var/lib verniy-drug
```

Папка `private/` внутри — это персональные данные. Бэкапы храните так же бережно: в России и с ограниченным доступом.

## Куда что складывается

```
$DATA_DIR/
  public/animals.json     карточки животных — уезжают на сайт
  public/media/           фотографии животных и опекунов
  private/applications.jsonl  ЗАЯВКИ: имена, телефоны — только здесь
  private/consents.jsonl      журнал согласий (доказательство по ч. 3 ст. 9 152-ФЗ)
  private/admins.json         учётные записи (пароли — хэш scrypt)
  private/sessions.json       сессии
  private/audit.jsonl         кто что делал в админке
```

Файлы в `private/` создаются с правами `0600` — читать может только владелец процесса.

## Что должен сделать приют по закону

Сайт закрывает техническую часть. Остальное — организационное, и без него штрафы:

- [ ] **Подать уведомление в Роскомнадзор** об обработке персональных данных (ст. 22 152-ФЗ) — бесплатно, через [pd.rkn.gov.ru](https://pd.rkn.gov.ru/). С 01.09.2022 обязаны почти все, включая НКО. Штраф за неподачу для юрлица — 100–300 тыс. ₽.
- [ ] **Приказом назначить ответственного** за организацию обработки персональных данных (ч. 1 ст. 18.1).
- [ ] Утвердить политику и локальные акты, ознакомить с ними сотрудников, у которых есть доступ к заявкам.
- [ ] Провести оценку вреда субъектам (формальность, но требуется).
- [ ] Держать сервер и бэкапы в России.
- [ ] Соблюдать сроки: удалить данные по отзыву согласия — **30 дней**; снять имя и фото опекуна с сайта по требованию — **3 рабочих дня**.

Тексты согласий, которые видят люди, лежат в `shared/consent.mjs` и опубликованы на сайте. **Перед запуском их стоит показать юристу по персональным данным** — это дешевле любого штрафа.

## Как приют публикует опекуна

1. Человек оставляет заявку. В форме он может отдельно и добровольно разрешить показать себя на сайте, а также установить запреты (например, «только имя, без фамилии») — приют обязан их соблюдать.
2. В админке в заявке видно, разрешена ли публикация.
3. В карточке животного заполняется блок «Опекун». Галочку «показывать на сайте» можно поставить, только указав, где и когда получено согласие.
4. Без галочки на сайте пишется просто «у животного есть опекун» — сам факт опеки персональными данными не является.

Если согласие получено не через сайт (голосом, в переписке) — сохраните подтверждение: скриншот, письмо, бумагу. Тексты для отправки человеку есть в админке на странице «Тексты согласий».
